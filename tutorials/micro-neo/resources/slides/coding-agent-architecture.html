Transcript

Keep tool calls and results paired

user Fix the failing test
assistant tool_call id=42 name=run_command
tool tool_call_id=42 "1 test failed"
assistant tool_call id=43 name=read_file
tool tool_call_id=43 "<file contents>"
Failure is still a result Unknown tools, invalid arguments, denial, timeout, and cancellation must close the call.
Identifiers preserve meaning The result ID tells the model exactly which request produced the observation.
Order stays deterministic Parallel tools may finish out of order, but transcript results should follow source order.
Persist complete messages Rendered terminal rows are presentation, not durable conversation state.
05 / 12
Tools

How tool calls work

The model returns a tool name and arguments. The agent validates the request, runs the tool, and records the result.

01 Decode

Convert provider JSON into your internal call type.

02 Validate

Reject malformed and unexpected arguments.

03 Confirm

Ask the user when an optional approval rule matches.

04 Execute

Run with a workspace, deadline, and cancellation.

05 Bound

Cap bytes, lines, duration, and images.

06 Emit

Send tool-call and tool-result events to the interface.

07 Append

Write the matching result into the transcript.

! Start with serial execution. Add concurrency only when every tool declares whether it is safe and result order remains stable.
06 / 12
Events and TUI

How events drive the TUI

Bubble Tea converts each agent event into new screen state.

assistant_text → append text
assistant_commentary → show status
parallel_start → create group
tool_call → show running tool
tool_result → show receipt
done / error → finish turn

The transcript is saved state. Events are live notifications. The TUI renders events and collects approvals, but it does not own the agent loop.

Safety

Where safety is enforced

Neo treats model tool calls as untrusted input. The host VM or sandbox provides the real security boundary.

1 Neo can ask for confirmation when a tool name or shell prefix matches.
2 The host sandbox limits access to files, processes, the network, and credentials.

Neo

How Neo is structured

Neo keeps the loop small and adds product features around it.

Agent coreinternal/agent

Loop and transcript

Owns messages, model calls, tool execution, events, steering, compaction, and turn limits.

Providersinternal/llm

Model adapters

Anthropic, OpenAI, OpenRouter, and Google use the same internal request and response types.

Product layercmd + tui + session

CLI, TUI, and sessions

The CLI starts chat or headless runs. Bubble Tea renders events. Sessions save transcript, model, provider, and usage.

Contextskills + projectctx + factory

Rules and subagents

Skills and AGENTS.md add task context. The agent tool starts supervised work or inspect subagents.

Tools, approvals, configuration, and prompt caching are separate packages that are wired together at startup.
