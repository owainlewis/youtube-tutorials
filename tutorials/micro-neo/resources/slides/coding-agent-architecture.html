04 / 12
The transcript invariant

Every call needs a matching result

user Fix the failing test
assistant tool_call id=42 name=run_command
tool tool_call_id=42 "1 test failed"
assistant tool_call id=43 name=read_file
tool tool_call_id=43 "<file contents>"
Failure is still a result Unknown tools, invalid arguments, denial, timeout, and cancellation must close the call.
Identifiers preserve meaning The result ID tells the model exactly which request produced the observation.
Order stays deterministic Parallel tools may finish out of order, but transcript results should follow source order.
Persist complete messages Rendered terminal rows are presentation, not durable conversation state.
05 / 12
Tools

The model requests. Your code executes.

A tool schema is an invitation. The runtime is the boundary that turns a request into a controlled side effect.

01 Decode

Convert provider JSON into your internal call type.

02 Validate

Reject malformed and unexpected arguments.

03 Authorize

Apply policy before any side effect.

04 Execute

Run with a workspace, deadline, and cancellation.

05 Bound

Cap bytes, lines, duration, and images.

06 Emit

Report lifecycle facts to interfaces and hooks.

07 Append

Write the matching result into the transcript.

! Start with serial execution. Add concurrency only when every tool declares whether it is safe and result order remains stable.
06 / 12
Events and the TUI

The UI is a reducer

new state = reduce(old state, event)

message_delta → append text
tool_start → active row
tool_update → partial output
tool_end → receipt
agent_end → clear status
error → visible failure

The transcript is durable state. Events are live notifications. The TUI never decides whether a tool runs.

09 / 12
Architecture evidence

Same mechanism. Different emphasis.

The strongest lesson comes from comparing where each product chooses to put complexity.

NeoGo

Direct boundaries

A policy-light core loop emits semantic events into a capable Bubble Tea interface.

Micro NeoGo

Teachable core

The provider, tools, transcript, loop, events, and interactive UI fit in one file.

PiTypeScript

Explicit lifecycle

A reusable low-level loop feeds session persistence, extensions, and UI components.

CodexRust

Product protocol

Typed events, request-scoped context, tool routing, safety, and multiple clients.

Claude Code adds public evidence for the same boundaries through documented hooks, permissions, sandboxing, project instructions, and isolated subagents.

Build order

Add complexity only when the next problem requires it

Stage 01

Model call

Interactive input and one text response.

Stage 02

One tool

Send a schema and execute a read request.

Stage 03

Agent loop

Append the result and call the model again.

Stage 04

Coding tools

Add exact edit and shell execution.

Stage 05

Events + TUI

Separate semantic facts from rendering.

Stage 06

Boundaries

Contain paths, time, output, and cancellation.

Stage 07

Sessions

Persist, resume, and compact valid history.

Stage 08

Extensions

Add hooks, skills, and subagents last.
