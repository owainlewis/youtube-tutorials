01 / Requirements & Planning

What are we building?

Decide what you need to learn before you code.

Planning output
Write down the outcome, audience, constraints, scope, and success checks before implementation.
PRD: Product Requirements Doc
  • →What are we building?
  • →Why are we building it?
  • →Who is it for?
  • →In scope / out of scope
Research phase
Using an external API or unfamiliar library? Ask the agent to inspect primary documentation and record relevant findings in research.md. Verify the source before building on it.
Prototyping as planning
A small throwaway version can test an interaction or technical assumption. Keep prototype code separate until you decide what should carry forward.
PRD Spec research.md Context files RALF research phase Throwaway prototype

03 / Breaking Down The Work

Break it into bounded tasks

One task. One agent. Reviewable increments.

The principle
Do not hand an agent the entire app and say "build this." Give it one bounded task with relevant context and checks so the change stays reviewable.
Task breakdown example
01Add email validation to signup form
02Create GET /users/:id endpoint
03Add rate limiting to auth routes
04Write tests for auth flow
Tool options
  • →Linear: issue tracking
  • →GitHub Issues: work beside the code
  • →Notion: flexible planning
  • →A plain document: simple and local

Choose a tool that fits the team. Keep the work small and reviewable in any of them.

AI helps here too
Ask the agent to propose bounded tasks with dependencies, acceptance criteria, and checks. Review the plan before creating tracker items.
Kanban Linear GitHub Issues Parallel agents Task decomposition

04 / Build

Brief the agent. Don't just prompt.

Context reduces avoidable guessing.

Without context
"Build me an auth system" leaves scope, security requirements, and existing patterns undefined.
With context
Requirements, design decisions, relevant files, constraints, and checks give the agent fewer gaps to fill.
What a good brief includes
  • 01Background on what you're building
  • 02Your technical design decisions
  • 03The specific task clearly stated
  • 04Patterns and conventions to follow
  • 05Things to avoid
Claude Code Cursor Kiro OpenCode Agentic loop YOLO mode Context window

05 / Review

Collect different kinds of evidence

Review every first pass.

01
Build
Agent completes the task
02
Self-review
Ask the implementation agent to inspect its diff. Treat findings as proposals to verify.
03
Human review
Understand what was built. Does it match the technical design?
04
Next task
Repeat the cycle
What self-review adds
A second pass may surface missing cases or mismatches. It is not independent evidence because the same system produced the code.
Common catches
  • →Edge cases & error handling
  • →Security vulnerabilities
  • →Missing input validation
  • →Performance issues

06 + 07 / Deploy & Monitor

Ship it. Then watch it.

Deployment is the beginning, not the end.

Deploy
An agent can prepare pipeline or infrastructure changes. Review the diff, tests, rollout, and rollback plan before a person approves deployment.
Production adds failure modes
Monitor the behaviour users depend on and the failures identified during design. Test the alert and rollback path.
Monitoring stack
⬤
Error tracking
Record actionable failures without sensitive data
◎
Uptime monitoring
Is it responding? Is it healthy?
△
Alerts
Route important signals to an owner
≡
Logs
Understand what happened when things go wrong
